General Information

A collection of 3305 single notes of 41 musical instruments (cf. Table 1) of different
historical periods was recorded and analyzed. The database includes the instrument
recordings, radiation patterns (directivities), and audio features such as the sound power
or spectral centroid. The database is provided under a Creative Commons BY-NC-SA
licence, giving you the freedom to redistribute, remix, transform, and build upon the
material for any purpose, but not for commercial purposes. For more information visit
https://creativecommons.org/licenses/by-nc-sa/4.0.
The documentation is focused on the structure and content of the database. More

information on the acquisition, processing and validation can be found in the accompa-
nying publications. If you use this database, please cite:

Ackermann, D., Brinkmann, F., Weinzierl, S. (2024). A Database with Directivities
of Musical Instruments. J. Audio Eng. Soc. DOI: https://doi.org/10.17743/jaes.

Figure 2: Data structure of the database.

The presented data set includes record-
ings and radiation patterns of the individ-
ual tones of 41 modern and historically
informed musical instruments which have
been measured with a 32-channel micro-
phone array in a anechoic environment [2].
The recordings and directivities are pro-
vided in standardised SOFA [3] format in
convection FreeFieldDirectivityTF [4].
Furthermore, averaged directivities are cal-
culated from these data for each instrument,
which are suitable for use in virtual acous-
tics. In addition, spatially high-resolution
directivities were generated in OpenDAFF1

version 1.5 and GLL2 format, which al-
low direct use in the simulation software
RAVEN [5] and EASE3, respectively.
The general data structure is outlined in

Figure 2. The database consists of 5 components: (0) this documentation, (1a) radiation
pattern of the single tones as SOFA files, (1b) one-third octave averaged directivities as
SOFA files, (1c) high spatial resolution directional patterns in openDAFF format and
(1d) in GLL format. (2) The recordings of the single tones of the instruments as SOFA
files, (3) audio features such as the sound power or spectral centroid as CSV file, (4)
pictures of the instruments during the recording and (5) and a Matlab script to read
and edit the SOFA data provided. All data were measured with a sampling frequency
of fS = 44.1 kHz.
The SOFA files can be read using a variety of APIs4. They can be loaded for example

using the Matlab/Octave API5:

obj = SOFAload('SourceName_midiNote_singleTones.sofa');

or with the sofar Python package6:

sofa = sofar.read_sofa('SourceName_midiNote_singleTones.sofa')

They contain the recorded signals and extracted directivities as complex transfer func-
tions (TFs) together with metadata describing the data in detail. This includes the
name of the Instrument in the entry GLOBAL SourceName, the name of the musician
in GLOBAL Musician, the manufacturer of the instrument GLOBAL SourceManufacturer

and a verbal description of the position of the instrument during the measurement in
SourceView Reference. The arrangement of the capsules of the microphone array is
described in ReceiverPosition.
In the SOFA data of the recordings and the single notes, the respective note and the

dynamic are indicated in GLOBAL Description, e.g. note = A4; dynamic = ff, and
in the MidiNote field the Midi number7, it is A4 = 69, where the frequency for A4

1a DirectivitiesSingleTones SOFA

There is a separate SOFA file for each Instrument, note and dynamic for the single tone
directivity data and the naming of the file corresponds to the scheme SourceName midi

Note singleTones.sofa. The purely real sound pressure levels are stored as complex
transfer functions in the field Data.Real with the dimension MxRxN, where M (measure-
ment) is always 1, R (receiver) = 32, and N refers to the number of the extracted partial
tones. The Data.Imag field with the dimension MxRxN is included in the dataset for
consistency reasons, but contains only zeros. The field N indicates the frequencies of the
fundamental and partials in Hz.

1b Directivities3rdOctave SOFA

For the one-third-octave averaged directivities, there is one SOFA file for each instrument
with the naming scheme SourceName 3rdOctave.sofa. The averaged and calibrated
sound pressures are stored in the Data.Real with the dimension MxRxN, where M is
always 1, R = 32, and N=31 refers to the nominal centre frequencies from 20 Hz to
20 kHz according to IEC 61260-1:2014 [6]. The data field Data.Imag has been filled
with zeros. The field N indicates the centre frequencies of the one-third-octave bands in
Hz. In this case, the entries SourceTuningFrequency, SteadyPart and MidiNote are
not included in this data representation.

1c Directivities3rdOctave OpenDAFF

The open source and freely available openDAFF format can be read with several APIs8.
The naming of the data follows the scheme SourceName.daff. The directional patterns
were stored with a spatial resolution of 5◦ (azimuth and colatitude), i.e. each file contains
absolute one-third octave spectra at 2522 points. This data can be used directly in the
acoustic simulation environment RAVEN.

1d Directivityies3rdOctave GLL

The proprietary GLL format enables the integration of complex sound sources into the
acoustic simulation environment EASE. The directional patterns averaged over a one-
third-octave were stored as 8192 long FIR filters with a spatial resolution of 5◦, with the
naming scheme SourceName.gll.

is fs = 44.1 kHz. The data is calibrated (i.e. a value of 1 corresponds to a pressure of 1
Pascal) and compensated for the frequency response of the microphone array.

Timbre-describing audio features were calculated for for a subset of the audio files.
Scales and special tones were excluded from this calculation.
Prior to the audio feature extraction, a main microphone was selected for each instru-

ment, based on the highest RMS over all notes. The audio features were then calculated
using the TimbreToolbox (TTB) [9]. The toolbox calculates various features describ-
ing the spectral distribution, respectively the harmonic content, as well as the temporal
envelope.
The spectral distribution descriptors are first calculated as time-varying features, re-

sulting from a frame-wise analysis of the audio data. Subsequently, the median and
interquartile range are obtained from the trajectories as single values. Features related
to the temporal envelope, are represented by single values for each recording.

4 Pictures

This folder contains pictures of the musicians during the recording and detailed photos
of the instruments.

5 Tools

The Directivity demo.m Matlab script makes it possible to read the recordings from
the SOFA data, display their spectrum graphically and transform them into the time

4



domain with the help of the IFFT. This data can then be saved in the script as a WAV
file and played back with common playback devices.

Furthermore, the script enables the three-dimensional representation of single-tone
and frequency-averaged directivity in the form of balloon plots based on the SOFA data
provided.
Finally, the data can be estimated to any quadrature using spherical spline interpo-

lation. The prerequisite for all processing steps is the installation of the freely available
AKTools9 and the SOFA API for Matlab, the so called SOFAToolbox, contained therein.
